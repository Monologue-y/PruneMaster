# 《剪枝 · Prune Master》游戏设计文档

版本：v1.0（最终交付版）

## 一句话

玩家扮演园艺师，在每一关把多棵相互纠缠的树木逐节点修剪干净；只有"当前没有任何子节点"的节点才允许下剪。

## 核心规则

1. **结构**：每棵树是数据结构意义上的树（父节点 → 子节点，逐层向下）。一个关卡包含多棵树。
2. **跨树关联**：一棵树的第二层节点可能是另一棵树的父节点；一个叶子节点可能同时是多棵树的非叶子节点。即：**关卡整体是一个有向无环图（DAG）**，节点可属于多棵树。
3. **可剪条件**：当且仅当节点当前**没有任何存活子节点**（出度为 0）时才可剪去。父节点必须等子节点全部剪完后才能剪。
4. **失误**：点击仍有子节点的节点 → 扣 1 点生命。共 3 点生命，扣完本关失败。
5. **通关**：剪掉本关**所有**节点。
6. **限制**：没有失败性倒计时或步数限制；系统持续记录通关用时，并在完成后给出成绩评级（数据格式仍预留 `time_limit` 字段，后期可作难度开关）。

## 通关计时与结果页

- 计时从关卡开始后累计，胜利或失败时冻结；HUD 顶部持续显示 `MM:SS`，失败页显示本次用时但不评级。
- S 级目标随节点数变化：`S = ceil(max(24, 12 + 节点数 × 1.6))` 秒。A 级上限为 `ceil(S × 1.4)`，B 级上限为 `ceil(S × 1.9)`，超过 B 级上限为 C 级。评级只提供挑战反馈，不影响解锁或判定失败。
- 通关结果页采用暗色遮罩和金色完成标题，集中展示 S/A/B/C 大号评级、通关时间、S 级目标和评级刻度；保留下一关、重试和返回选关操作，第 20 关自动隐藏下一关按钮。
- 例：第 1 关共有 19 个节点，S 级目标为 43 秒；37 秒完成时显示 S 级。

## 数学性质（关卡设计与引擎的基石）

设关卡图为有限 DAG，"剪枝" = 删除一个出度为 0 的节点：

- **定理 1（无死局）**：任何非空有限 DAG 至少存在一个出度 0 的节点。→ 任何局面下玩家总有可剪的节点。
- **定理 2（顺序无关）**：删除汇点后的子图仍是 DAG。→ **任何合法剪枝顺序都能通关**。
- **推论**：本作的难度不来自决策策略，而 100% 来自**视觉辨识**——从盘根错节的枝条中判断"哪个节点现在没有子节点"。因此：
  - 美术的**醒目度与层级清晰度**是核心可玩性，不是装饰；
  - 关卡数据的**无环性**必须由校验器强制保证（成环 → 环上节点永远不可剪 → 死局）。

## 玩法体验细则

- 布局：节点位置与树结构解耦，以蜂窝点阵随机旋转散布；枝条的父端较粗、子端较细，玩家依靠粗细方向判断父子关系。
- 点错反馈：节点抖红 + 扣心（不额外高亮其子节点，保留辨识挑战）。
- 剪枝动画：节点颤抖 → 缩放消失；其所有入边连线回缩。"树枝断成两截"为 M6 可选增强。
- 跨树共享节点用醒目橙色高亮，提示玩家"这个点同时属于多棵树"。
- 长按任意节点进入常驻检查模式，高亮真实连接的枝条与相邻节点；轻点任意处退出，缩放和平移不会中断检查。

## 视觉方向（M3 落地）

- 整体贴近真实树木：程序化贝塞尔树枝使用树皮纹理、深色描边与 17px→4.5px 渐窄宽度，支撑任意几何的跨树连线。
- 节点使用统一绿色叶簇；共享节点增加橙色外圈，避免按树着色造成视觉噪声。
- 背景使用固定亮色暖纸到浅薄荷渐变，菜单与游戏统一，并以深色文字保证对比度。
- 音效包括剪枝、错误、点击、胜负反馈及无缝循环风声 BGM，均由脚本生成。

## 难度设计

难度轴（按顺序叠加）：树数 → 节点数 → 跨树连线密度 → 视觉干扰。

**周期制（非线性递增）**：以 4 关为周期从第 1 关起循环 5 轮——简单 → 中等 → 中等 → 困难。L1 是单独手工调校的 19 节点教学关；后续简单关为 26 节点/3 树/1 共享，中等关为 52/4/2，困难关为 100/6/4，第 4 周期起共享桥 +1。即 L1 简（教学）L2 中 L3 中 L4 难 | … | L20 难（压轴）。

**布局**：所有难度统一"位置与树结构完全解耦"（蜂窝点阵随机旋转散布 + 随机连边），简单关也不保留树形规律；难度差异由节点规模承载。
